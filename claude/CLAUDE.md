# CLAUDE.md — 全局指南

## 适用范围与优先级

- 作为 Claude Code 用户级指南供任务继承；项目或子目录的适用 `CLAUDE.md`、`AGENTS.md` 可覆盖对应范围。遵循更高优先级的平台约束；用户显式指令 > 子目录指南 > 全局指南 > 其他项目约定。
- 用户显式指令与本指南冲突时，按授权执行，并在前置说明记录原因、影响范围和回滚思路。
- 新文件使用 UTF-8（无 BOM）。与用户的会话沟通及交付说明使用中文；代码注释、代码中出现的文字（包括字符串、日志、错误信息、命令帮助和示例输出）、Git Commit 提交信息、PR 标题与描述、Issue 等默认均使用英文书写，不用中文。

## 工作与权限边界

- 仅运行安全命令，禁止 `rm -rf` 等破坏性操作，禁止泄露或上传敏感信息。网络默认仅用于读取公开资料，优先官方与权威来源；外部写入须有用户明确授权。
- 远端 CI/CD 策略：对于用户个人仓库 `yuluo-yx` 下的 `typo` 与 `mory` 两个仓库（即 `yuluo-yx/typo` 和 `yuluo-yx/mory`），日常提交允许跳过 CI，在提交信息（Commit Message）中添加 `[skip ci]`；其他所有仓库均默认启用 CI，正常触发远端 CI/CD 流程，严禁添加 `[skip ci]` 或禁用远端 CI。
- 软件发布策略：软件发布尽量使用 GitHub CI 执行。若发布失败两次且仍不确定原因，必须先在本地执行 build 复现并排查修复后，再重新发布。对于 `yuluo-yx` 下的所有个人自用软件仓库（如 `yuluo-yx/typo`、`yuluo-yx/mory` 等凡包含 `yuluo-yx` 的仓库），在发布时无需检查安全漏洞（例如 Node、Go 等依赖或代码安全漏洞扫描）。
- 保留用户已有改动，不覆盖其他任务内容；仅操作授权范围。不得在工作目录外新增无关目录或使用线下介质保存制品。
- 临时文档与中间产物清理：在 debug 或功能编写过程中产生的所有临时文档、排查记录、计划草稿等中间产物，在任务结束前必须全部清理删除，避免占用存储空间；仅当判断某份文档确有必要长期保留时，必须先向用户询问，由用户决定是否保留，否则一律清除。
- 优先复用标准库、主流稳定库或官方 SDK，避免重复自研；记录实际替换情况。
- 不添加与需求无关的安全基线或设计；移除多余设计仍须在授权范围内，记录结果，不得借此绕过必要权限边界。
- 允许清理过时代码和不兼容替换，但交付必须写明迁移方案，或明确“无迁移，直接替换”。禁止 MVP、占位实现和 `NotImplemented`。
- 新增或修改代码时补齐必要的英文代码注释与英文文档说明。输出中断后基于已完成内容续写。

## 工具与证据

- 环境事实以当前可调用工具为准，其次为 Claude Code 实际加载的设置（如适用层级的 `settings.json`），历史记录只作已核实的补充。不得强绑定不存在的 MCP 或工具。
- 默认用 `rg --files` / `rg -n` 定位，按行读取相关上下文；文本和配置优先用当前可调用的 `Edit` / `Write` 精确编辑，有 `apply_patch` 时也可按最小差异使用。安全 shell 用于检索、批处理与本地验证。它们是正常工具路径，不因没有符号级 MCP 反复请求许可。
- 复杂任务记录简明计划、证据、决策和验收结果；有可用计划工具时使用，没有时用任务内文本记录。无需输出内部思考过程。
- 外部检索优先可用的官方文档工具；Context7、Fetch 可用且适用时按此前后顺序选择，需要浏览器交互时才用 Playwright；否则选择当前实际可用的网页工具。记录关键词、筛选条件、访问日期和采用依据。
- 需要下载或切换 SDK 时，先用 `mise list` 核对，再通过 `mise` 管理。
- HTTP 429 固定退避 20 秒；HTTP 5xx 或超时退避 2 秒后最多重试一次。仍失败时给出保守离线结果、证据缺口和下一步建议。
- 实际工具降级须在前置说明记录原因、范围和回滚方式，交付说明记录文件清单与验证结果；存在任务内记录位置时同步保存摘要。

## 历史与记忆：先定位，再回读

- 先使用当前工作区证据。仅在任务需要历史信息时，按路径、日期、任务标识和关键词定位 `history.jsonl`、`projects/` 或实际可用的记忆目录中相关条目，再读取少量原文及必要上下文；信息不足时逐步扩大范围。
- 不默认整读历史文件、记忆索引或全部技能正文。技能先看入口、描述和引用，选中后只读适用流程；引用历史结论须给出具体文件或记录定位。
- 当前工具或配置与历史不一致时，以当前事实为准，说明时效和不确定性。
- 正式记忆写入前，先定位并遵守原有写入网关，检查未闭合事务及归属。不得直接写数据库或绕过网关；网关缺失时保留任务内摘要，说明正式记忆未写入。
- 遇到其他任务的事务或归属冲突，只暂停受影响部分，继续独立工作，不接管、不覆盖。任务收尾可沉淀已验证经验，但记忆写入仍遵守上述网关。
- 实验性上下文管理服务于同一任务跨窗口的笔记及历史消息、工具结果检索，不代表自动检索所有其他对话。

## 实施、验收与交付

1. 定位适用指南、代码、配置和必要证据，明确目标、范围、假设、时效与不确定性。
2. 复杂任务维护步骤、状态和验收标准；小步修改，配置与指南调整前保留不覆盖旧备份的可恢复备份。
3. 本地执行适用构建、静态检查和关键路径测试。构建/静态检查零报错，测试矩阵通过，覆盖率目标 `>= 90%`，非 `yuluo-yx` 仓库依赖无高危 CVE（`yuluo-yx` 下的个人软件发布时免除 Node、Go 等安全漏洞检查）；流程可重复、版本锁定、可回滚。不得用精简上下文降低这些门槛。
4. 关键路径覆盖单元、集成、契约、E2E、性能、压力、容量、混沌与回归验证；根据任务列出适用项及未验证项，不得虚称不适用项已通过。观测采用轻量方案，禁止 Prometheus/OpenTelemetry 体系。
5. 交付说明列出文件、行为变化、验证命令与结果、证据来源、风险、未完成项、回滚方式和最后验证日期；保留用户明确要求的交付数量。没有实际用量对比，不把字符变化宣称为 Token 或套餐节省。
6. 软件发布尽量通过 GitHub CI 完成；若发布连续失败两次且原因仍不明确，须先在本地 build 复现问题并解决后再重新发布。非个人自用仓库的发布任务按需准备迁移脚本、割接窗口和回滚方案。任务结束前清除 debug 或功能开发过程中生成的临时文档、快照与中间产物；若认为确需持久化保存，须先征得用户同意。

## Claude Code 适配

- 本指南以本机 `~/.codex/AGENTS.md` 的通用规则为基准；Claude Code 的工具、设置和历史路径按实际环境适配，不把 Codex 专属配置当作 Claude Code 的执行前提。
- 开始项目任务时主动定位并读取适用的 `CLAUDE.md`、`AGENTS.md` 与明确项目规范；不假定 `AGENTS.md` 会被 Claude Code 自动加载。不要在发现规则冲突时绕过更高优先级的平台约束。
- 未经用户明确要求，不提交、不打标签、不推送、不创建 PR、不发布，也不改变远端状态；已有授权范围内的操作不重复索取同一授权。
- `~/.claude/agents/`、`skills/`、`commands/`、`hooks/`、`plugins/` 可作为候选能力来源，存在目录不等于能力已经加载。技能先定位入口与描述，再按任务读取；只有用户或适用项目指南明确授权时才委派子代理。
- UI 任务按需使用前端设计能力并遵守项目设计系统；复杂任务按需使用规划能力，但落盘计划受临时产物清理与仓库规范约束。GitHub 命令或插件不能替代提交、推送与发布授权。
- hooks 是辅助防线，不能替代权限检查、敏感信息审查和验收。不得将模型名称、运行时版本、插件加载状态或历史配置错误写成未核实的当前事实。
- Claude Code 自动记忆与正式记忆网关分别按实际配置核实；不能用自动记忆文件绕过正式记忆的写入网关、事务归属或用户授权。
